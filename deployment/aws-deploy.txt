Decide first: the DB (~1.1 GB)
  Option A (demo, simplest): bake the DB into the image.
     - remove the "data/db/" line from backend/.dockerignore
     - rebuild -> image ~2.9 GB, self-contained, no S3, no boto3.
  Option B (prod, clean): keep the DB in S3, download on startup.
     - aws s3 cp backend/data/db/hm.duckdb s3://<bucket>/warehouse/
     - add ~5 lines of boto3 in main.py lifespan to download if missing.
  For the demo -> Option A.


1. Put the keys in Secrets Manager (never in image / git)
   aws secretsmanager create-secret --name retail/keys \
     --secret-string '{"DEEPSEEK_API_KEY":"sk-...","PERPLEXITY_API_KEY":"pplx-..."}'


2. Push the image to ECR (AWS docker registry)
   aws ecr create-repository --repository-name retail-copilot-api

   aws ecr get-login-password --region <REGION> | \
     docker login --username AWS --password-stdin <ACCT>.dkr.ecr.<REGION>.amazonaws.com

   cd backend && docker build -t retail-copilot-api .          # (Option A: DB baked)
   docker tag  retail-copilot-api:latest \
     <ACCT>.dkr.ecr.<REGION>.amazonaws.com/retail-copilot-api:latest
   docker push <ACCT>.dkr.ecr.<REGION>.amazonaws.com/retail-copilot-api:latest


3. Create the ECS Fargate service (console is easiest the first time)
   Task definition:
     - image    : <ACCT>.dkr.ecr.<REGION>.amazonaws.com/retail-copilot-api:latest
     - cpu/mem  : 1 vCPU / 2 GB (Prophet is CPU-bound; start small, autoscale on CPU)
     - port     : 8000
     - secrets  : retail/keys -> env vars DEEPSEEK_API_KEY, PERPLEXITY_API_KEY
     - IAM role : ecr pull, secretsmanager:GetSecretValue
                  (+ s3:GetObject only for Option B)
   Service:
     - behind an Application Load Balancer (ALB), HTTPS via an ACM cert
     - health check path : /health
     - ALB idle timeout  : 120-300s (so a streaming SSE run is not cut off)

   Cost: Fargate has no free tier (~$9-10/mo if 24/7). For a demo, start the
   task only during the demo and stop it after.


4. Host the frontend on S3 + CloudFront (free tier)
   cd frontend && npm run build            # -> dist/   (DONE)
   # bucket already created: surya-retail-copilot-web (us-east-2, private)
   aws s3 sync dist/ s3://surya-retail-copilot-web/   # upload the build

   CloudFront:
     - origin 1: the S3 bucket (OAC) for the SPA
     - origin 2: the ALB for /api/*   -> same domain, so no CORS, matches the
                 frontend's /api proxy exactly
   Cost: CloudFront "Always Free" = 1 TB/mo + 10M requests. Demo = $0.

   (Alternative: host the frontend on Cloudflare Pages, free + simplest, but it
    is a different domain so you add one CORS rule on the backend.)


5. (optional) CI/CD
   Backend  on push: docker build+push -> ECR, then
                     aws ecs update-service --force-new-deployment
   Frontend on push: Cloudflare Pages auto-deploys, or s3 sync + CloudFront invalidate.


What we deliberately skip (and why)  --  full rationale in design/deployment.md
   Bedrock      : extra per-token AWS cost; the DeepSeek/Perplexity keys are
                  already paid for. Use only when going AWS-native (IAM, no keys).
   SageMaker    : Prophet/SARIMA are in-process, second-long fits; no endpoint needed.
   RDS/Redshift : the data is a read-only single file; embedded DuckDB is right.
   Lambda (app) : streaming + heavy deps + long requests fight Lambda.
